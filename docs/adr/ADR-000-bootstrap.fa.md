# ADR-000: اسکلت و توسعه‌های مرحله‌ای

وضعیت: پذیرفته‌شده برای bootstrap. تاریخ: ۲۰ اکتبر ۲۰۲۶. [English](ADR-000-bootstrap.en.md)

از ۲۰۲۶-۱۰-۲۲، [ADR-006](ADR-006-default-sqlserver.fa.md) بخش profile‌های SQL Server و اجرای عادی را جایگزین کرده است. متن تصمیم اولیه در ادامه به‌عنوان سابقه حفظ می‌شود.

## مسئله و تصمیم اولیه

می‌خواهیم خرابی زیرساخت، نتیجهٔ build خود starter را مبهم نکند. برای مثال، در تصمیم اولیه نبود SQL Server نباید مانع تست HTTP سلامت می‌شد. این بخش تصمیم تاریخی است و تغییر اجرای عادی در ADR-006 را باید جدا در نظر گرفت.

Java 21، Maven wrapper و Spring Boot 4.1.1 انتخاب شدند و SQL Server هدف persistence است. در تصمیم اولیه، SQL Server، Redis، Kafka و JWT profile صریح Maven دارند. startup پیش‌فرض، health روی loopback را بدون سرویس خارجی اجرا می‌کند.

## profile‌ها چه چیزی را کنترل می‌کنند؟

Maven profile، dependency‌های بسته و Spring profile، تنظیم runtime را تعیین می‌کند. هر دو باید مستند باشند. وجود dependency و config پیاده‌سازی قابلیت مالی نیست.

- Redis نسخهٔ پاسخ ماندگار را نگه می‌دارد.
- Kafka غیرهم‌زمان است.
- OTP به intent متصل به عامل احرازشده نیاز دارد.
- Debezium زیرساخت خارجی مرحلهٔ بعد است.

در متن اولیه، پروتکل مالی و schema در دفتر تصمیم‌ها پیشنهادی‌اند.

## هزینه و روش بررسی

فرمان‌های profile طولانی‌تر می‌شوند و هر classpath، build/test gate خودش را می‌خواهد. smoke test پیش‌فرض، classpath کامل یا SQL Server واقعی را تأیید نمی‌کند. CI کتابخانه‌های مرحله‌ای را جدا compile می‌کند و integration test واقعی همراه feature می‌آید.

H2 یا غیرفعال‌کردن migration را موفقیت تست SQL Server معرفی نکنید.

## مختصات Spring Boot

Initializr مختصات ناموجود `4.1.1.RELEASE` تولید کرد. آن را به نسخهٔ منتشرشدهٔ `4.1.1` اصلاح و build را بررسی می‌کنیم. جزئیات در راهنمای starter و نتیجهٔ واقعی پس از اجرا در گزارش evidence ثبت می‌شود.
