# ADR-007: حسابداری دوطرفه از V1

وضعیت: طراحی پذیرفته‌شده در ۲۰۲۶-۱۰-۲۲ توسط مالک پروژه با انتخاب گزینهٔ E. پیاده‌سازی و شواهد SQL Server وجود ندارد؛ کارایی اندازه‌گیری نشده است. [English](ADR-007-double-entry-ledger.en.md)

## تصمیم و زمینه

چهار جدول `accounts`، `operations`، `journals` و `postings` در همین سرویس و SQL Server استفاده شوند. تاریخچهٔ posting شواهد مالی تغییرناپذیر و موجودی ماندگار حساب projection هم‌زمان آن است. سند متوازن کامل، projectionها و نتیجهٔ موفق عملیات با هم commit شوند. رد درخواست سند و posting ندارد و retry پاسخ ذخیره‌شده را بدون ثبت مالی مجدد می‌دهد. افتتاحیه عملیات داخلی سنددار و credit/debit دارای حساب مقابل تأمین/تسویه باشند.

این تصمیم بند اختیاری/آینده‌بودن double-entry در ADR-003 و شروع دوجدولی را جایگزین می‌کند. معماری پذیرفته شده است؛ جزئیات قید، هویت، قفل و امنیت ADR-001–005 همچنان نیازمند مرورند. [Ledger.md](../fa/Ledger.md) قواعد علامت، نمونه، تطبیق و تحویل مرحله‌ای را توضیح می‌دهد. این توسعه انتخاب کاربر است و نیازمندی شرکت معرفی نمی‌شود.

## گزینه‌ها و هزینه

ذخیرهٔ صرف موجودی بازسازی تاریخچهٔ حسابداری نمی‌دهد. رکورد ثابت دوحسابی ساده‌تر است ولی ثبت چندسطری آینده را محدود می‌کند. لایه‌های اضافی انتقال و تراکنش دفترکل مانند BankingLedger یا سرویس مستقل، چرخهٔ بیشتر و مرز توزیع‌شدهٔ غیرضروری دارند. مدل منتخب چند posting را در یک تراکنش محلی پشتیبانی می‌کند. SQL schema جدا ضمانت حسابداری اضافه نمی‌کند.

هزینه شامل فضای سند و posting، index، نوشتن log، reconciliation و رقابت ردیف تأمین مشترک است. در CBS21–22 اندازه‌گیری شود و invariant برای ادعای سرعت تضعیف نشود. FX آینده مرور مستقل ارز، clearing و رزرو می‌خواهد.

## پیاده‌سازی و پذیرش

[ماتریس قیدها](../fa/Database-review.md) و CBS02–04 پیش از اولین migration مالی مرور شوند. قواعد دامنه، migration چهارجدولی، mapping و مسیرهای عملیات در همان کارهای هدایت‌شده اضافه شوند. مراحل آینده یک‌جا اجرا و معیار یادگیری بدون شاهد بسته نشوند. تست SQL Server شامل رقابت، duplicate، افتتاحیه، تغییرناپذیری، rollback مرزهای نوشتن، restart و بازسازی مستقل باشد. اصلاح آینده با سند معکوس جدید انجام می‌شود؛ endpoint reversal در V1 نیست. اکنون schema یا migration داده‌ای برای rollback وجود ندارد. تغییر آیندهٔ تاریخچهٔ ثبت‌شده migration رو به جلو، مرور و حفظ هویت لازم دارد.
