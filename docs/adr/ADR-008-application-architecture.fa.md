# ADR-008: مونولیت ماژولار و مرز featureها

وضعیت: طراحی پذیرفته‌شده توسط مالک پروژه در ۲۰۲۶-۱۰-۲۳. [English](ADR-008-application-architecture.en.md)

زمینه: نوشتن مالی یک commit محلی می‌خواهد و HTTP، قواعد دامنه و persistence باید قابل‌فهم و قابل‌تست بمانند.

تصمیم: یک deployment از Spring Boot با سازمان‌دهی feature-based، مسئولیت‌های api/application/domain/persistence و port/adapter انتخابی. قواعد Money/Account/Journal مستقل از framework و تراکنش تحت مالکیت coordinator مبنا هستند. persistence حساب و دفترکل بخشی از عملیات را جدا commit نمی‌کنند. مرز چهارجدولی ADR-007 و TransactionTemplate پذیرفته‌شده حفظ می‌شوند.

[Architecture.md](../fa/Architecture.md) درخت package، جریان درخواست، مثال انتقال/Money و ساختار تست/resource را ثبت می‌کند. نام کلاس آینده مثال است، نه API موجود. packageها تدریجی ایجاد شوند؛ لایهٔ خالی و سرویس دفترکل جدا نسازیم.

گزینه‌ها: لایه‌بندی صرفاً فنی مالکیت feature را پنهان می‌کند؛ سرویس جدا مسئلهٔ سازگاری توزیع‌شده می‌آورد؛ framework عمومی event sourcing برای نیاز فعلی لازم نیست. شکل CQRS، ابزار کنترل مرز و الگوهای دیگر پیشنهادند و پذیرش جدا می‌خواهند؛ این ADR آن‌ها را نمی‌پذیرد.

هزینه: نگاشت و interface صریح و رعایت مرز persistence ماژول‌ها. اندازه‌گیری کارایی/هزینه نداریم. تست دامنه و در صورت نیاز کنترل ساختار اضافه شوند؛ ادعای persistence/قفل همچنان تست واقعی SQL Server می‌خواهد. پذیرش طراحی فاصلهٔ ارزیابی یا مرور CBS00–04 را نمی‌بندد.

پیاده‌سازی: Money و bootstrap وجود دارند؛ بقیه برنامه‌اند. migration یا dependency عوض نشده است. بازگشت از ساختار به هماهنگی import و مستندات نیاز دارد؛ refactor package تاریخچهٔ مالی را برنمی‌گرداند.

تصمیم بعدی: ADR-009 در ۲۰۲۶-۱۰-۲۳ CQRS تک‌دیتابیسی را می‌پذیرد؛ وضعیت پیشنهادی متن بالا سابقهٔ تصمیم است. سایر الگوها دامنهٔ اعلام‌شدهٔ خود را دارند.
